# Автокопирование китов — как устроено

Документ — для владельца: что есть в модуле на сегодня и почему так.
Модуль торгует по-настоящему (OKX), бэктест — повтор истории по тем же
правилам.

| Часть | Файл | Что делает |
|---|---|---|
| Торговля | `WhaleScanner/tools/autotrade_live.py` | Служба `whale-autotrade`: сигналы китов из базы бота, вход и выход на OKX, бэктест ночью и по кнопке, автоочистка (разделы 8–15) |
| Бэктест-повтор | `WhaleScanner/tools/autotrade_replay.py` | История сделок китов через тот же код сигналов и те же правила; свечи OKX; итог для вкладки (раздел 16) |
| Общее | `WhaleScanner/tools/autotrade_core.py` | База бота только на чтение, коды сделок, окно китов, имя бумаги на OKX, публичный запрос к OKX, предел памяти |
| Модуль API | `Wallet-Tracker/wt_autotrade.py` | Читает файлы службы, пишет «Старт»/«Стоп» и запрос пересчёта; ни процессов, ни потоков |
| Маршруты API | `Wallet-Tracker/whale_api.py` | Четыре адреса `/api/owner/autotrade…`, только для владельца |
| Вкладка | `Wallet-Tracker/src/screens/AutotradeScreen.tsx` | Экран «Автоторговля»: торговля, кнопки, бэктест |

Прежний бэктест-сетка (`autotrade_backtest.py`: сотни наборов параметров,
свечи Hyperliquid) удалён 22.11.2026 вместе с тестами: служба его больше не
запускала, а живой бот и повтор брали из него только окно китов и разбор
базы — это теперь в `autotrade_core.py` (раздел 17).

---

## 1. Как идут данные — коротко

1. Бот (C++) пишет каждую сделку китов Hyperliquid в `hyperliquid.db`, таблица `hl_fills`.
2. Служба `whale-autotrade` раз в 5 секунд читает новые сделки открытия
   (только чтение базы), ведёт окна китов по бумагам и сторонам и решает
   по правилам владельца, входить ли (разделы 8, 12, 13, 15).
3. Раз в 15 секунд сверяет счёт OKX: позиция, тейк, выход вслед за китом в
   убытке, разовое усреднение.
4. Пишет состояние (`live/state.json`) и сделки (`live/trades.jsonl`) —
   API отдаёт их вкладке.
5. Ночью в 03:17 UTC и по кнопке «Пересчитать сейчас» запускает
   бэктест-повтор последних 30 дней отдельным процессом с низким
   приоритетом; ход — во вкладке.

Ключи OKX — только в `/etc/whale-autotrade.env` у службы; в файлах модуля,
коде и ответах API их нет.

---

## 2. Модуль API — `Wallet-Tracker/wt_autotrade.py`

API сам ничего не считает и не торгует — в нём нет ни процессов, ни
потоков (раньше бэктест шёл внутри API и ядро трижды за ночь убило службу
API по памяти).

- **`DATA_DIR`** — каталог модуля `~/WalletTracker/autotrade_data/`
  (служба API может писать только сюда);
- **`is_on` / `_set_on` / `_try_set`** — выбор владельца в `switch.json`
  («Старт»/«Стоп»); записать не удалось — причина во вкладку, а не 500;
- **`trigger`** — «Пересчитать сейчас»: файл-запрос `run.request` службе;
- **`start_cmd` / `stop_cmd`** — «Старт» (итога ещё нет — заодно запрос
  пересчёта) и «Стоп» (служба перестаёт входить в сделки и прерывает
  пересчёт; позиция, тейк и выход вслед за китом остаются);
- **`latest`** — итог бэктеста-повтора `latest/summary.json` (итог прежней
  сетки, если остался на сервере, не показывается);
- **`backtest_status`** — ход пересчёта из `backtest_status.json`;
- **`live`** — состояние реальной торговли, приведённое к договору с
  вкладкой (испорченная строка — без неё, а не без ответа);
- **`status`** — всё это одним ответом вкладке.

## 3. Маршруты API — `whale_api.py`

- **`is_owner`** — владелец — только тот, чья подпись Telegram сошлась и
  чей номер равен `WHALE_OWNER_CHAT`.
- **`_owner_or_404`** — чужому — тот же 404, что у несуществующего адреса:
  о модуле не узнать. В журнал — `[AUTO] чужой запрос`.
- **`/api/me`** — поле `owner: true` только у владельца.
- **GET `/api/owner/autotrade`** — `status()`; **POST …/run** — `trigger()`;
  **POST …/start**, **…/stop** — `start_cmd()` / `stop_cmd()`.

## 4. Вкладка — `AutotradeScreen.tsx`

Ответ сервера проверяется до показа (`src/lib/autotrade.ts`): поле не того
типа — «нет связи», а не упавший экран; испорчен только итог бэктеста —
без него. Сверху — модуль вкл/выкл, кнопки, пересчёт (последний, следующий,
ход идущего), затем «Реальная торговля на OKX» (бот, ошибка, ключ, капитал,
позиция, выход, усреднение, ручные позиции, пропуски за сутки, статистика,
сделки, журнал), ниже — бэктест-повтор (общая статистика, открытая
позиция модели, правила, критерий, сигналы, последняя четверть и первые
три, кривая капитала, разбивки, последние сделки).

## 8. Реальная торговля на OKX — `tools/autotrade_live.py`

Отдельная служба `whale-autotrade` (`deploy/whale-autotrade.service`). Ключи
OKX есть только у неё: `/etc/whale-autotrade.env` (root, 600), API и бот их
не видят. Установка один раз владельцем: `sudo bash /home/vadymdota2/WhaleScanner/tools/autotrade-install.sh`,
ключ — `sudoedit /etc/whale-autotrade.env` (API key, Secret key, Passphrase;
права ключа — только «Торговля», привязка к IP сервера), затем
`sudo systemctl restart whale-autotrade`.

- **`Okx`** — подписанный REST OKX v5 (HMAC-SHA256: время + метод + путь + тело);
  `OKX_SIMULATED=1` — демо-счёт.
- **`Signals`** — каждые 5 с новые сделки китов из `hyperliquid.db` (только
  чтение) → окна 2 часа по бумаге и стороне (тот же `Window`, что в бэктесте).
  Сигнал — от 2 китов от 1000 $; старше 15 минут — момент ушёл.
- **`Trader.try_enter`** — вход, только если: модуль включён «Старт»; на
  счёте **нет ни одной позиции** (и ручной тоже); в бумагу не входили 3 часа;
  бумага есть на OKX и цена сходится с ценой китов ±2 %; цена не хуже
  средней китов больше чем на 0,3 %. Размер — 10 % капитала × 10×, кросс,
  рыночный ордер; затем тейк +1 % лимитным ордером (reduce-only). Сначала
  запись «входим», потом ордер — после падения повтора не будет.
- **`_track_open`** — каждые 15 с: позиция есть — тейк на месте (снят —
  ставится заново); позиции нет — сделка записывается из истории позиций
  OKX (PnL, комиссия, фандинг), оставшийся тейк снимается.
- **«Стоп»** — новых входов нет; позиция и тейк остаются (бот никогда сам не
  закрывает).
- Код обновился (автодеплой) — трейдер выходит, systemd поднимает новый
  (идёт пересчёт — сначала дожидается его).
- **Адрес OKX** — `Okx.detect`: ключ ищется на www, eea (европейский
  аккаунт, вход через my.okx.com), us; рабочий запоминается.
- **`Backtests`** — пересчёт бэктеста в этой службе: ночью в 03:17 UTC и по
  `run.request`, пока модуль включён; nice 19, предел 1200 МБ, пауза 15 с к
  Hyperliquid; итог — `latest/` (прежний — `prev/`); «Стоп» прерывает. Если
  служба поставлена со старым пределом памяти (меньше 1600 МБ), пересчёт
  не запускается — вкладка говорит «переустановите».
- Состояние — `~/WalletTracker/autotrade_data/live/` (`state.json`,
  `trades.jsonl`, `live.log`); API отдаёт его вкладке (`wt_autotrade.live`).
- Тесты — `tests/autotrade_live_test.py`: поддельная OKX, без сети и денег.

### Ручная сделка владельца на счёте

Бот видит все позиции счёта (бессрочные, срочные, маржу). Позиция, открытая
не его ордером (метки `wtin…` нет), — ручная владельца:
- бот всё равно входит, но маржой **5 %** капитала, а не 10 %
  (`MARGIN_FRAC_SHARED`); в записи сделки — `margin_pct`;
- на ту же бумагу бот не входит: в режиме net его сделка вычлась бы из
  ручной, а его тейк закрыл бы часть ручной;
- тейк бота — только на его объём, даже если позицию на бумаге докупили;
- своя позиция бота, которую он не смог принять (цена входа не по рынку), —
  не «ручная»: пока она есть, новых входов нет.

### Автоочистка — `Janitor` (раз в 10 минут)

- окна китов по бумагам без новых сделок — выбрасывается старше 2 часов,
  пустые удаляются; список «входили в бумагу» — только за последние 3 часа;
- `live.log` больше 5 МБ — в `live.log.1` (одна старая копия), так же
  `last_run.log`;
- кеш свечей бэктеста — старше 30 дней удаляется, больше 500 МБ — удаляются
  самые старые (во время пересчёта не трогается);
- сборка мусора; служба всё равно больше 400 МБ — выходит, systemd
  поднимает её заново (не посреди входа в сделку и не во время пересчёта;
  позиция и тейк — на бирже, состояние — в файле).

Проверено: 10 суток опросов раз в 5 минут на базе в 1,2 млн ордеров — память
службы ровно 24 МБ.

Вход — всегда рыночным ордером, выход — всегда лимитным по цене тейка
(тест `OrderTypeTest`): бот никогда не закрывает позицию по рынку.

## 10. Жёсткая построчная ревизия торговли — что найдено и исправлено

Каждая ошибка закрыта проверкой (`ReviewTest` в `tests/autotrade_live_test.py`):
все эти проверки падают на прежнем коде и проходят на новом; места — под
мутациями (`tools/mutate-autotrade.py`).

| # | Ошибка | Чем грозила | Как теперь |
|---|---|---|---|
| 1 | Рыночный ордер ушёл, проверка исполнения упала обрывом сети; биржа ещё не показала позицию | **второй рыночный ордер** по следующему сигналу — две позиции бота | запись «входим» держится, пока сверка счёта (`resolve_entering`) не примет позицию по метке ордера или не снимет запись через 10 минут; до тех пор новых входов нет |
| 2 | Шлюз OKX ответил 502 (не JSON) на ордер, а ордер исполнился | бумага «исключена», а в том же шаге — вход по другой бумаге: две позиции | ответ не от биржи (не 5-значный код OKX) — не отказ, а «сверка» |
| 3 | Рыночный ордер отменён биржей без исполнения | бот записывал позицию, которой нет, и ставил тейк | позиции нет, пауза по бумаге 15 минут |
| 4 | Исполнение не подтверждено (`live`, исполнено 0) | позиция размером 0 в записи | ждать сверки |
| 5 | Режим long/short: у владельца встречная позиция на той же бумаге | бот принимал ручной шорт за свой лонг: не видел закрытия и ставил на него тейк | своя позиция — та же бумага **и та же сторона** |
| 6 | Тейк бота исполнился, а позиция на бумаге осталась (владелец докупил) | бот ставил новый тейк — закрывал часть **ручной** позиции | тейк исполнен (`get_order`) — сделка записана, нового тейка нет |
| 7 | После закрытия снятие остатка тейка упало | сделка записывалась **каждые 15 секунд заново** | сначала запись и «позиции нет» в файл, потом снятие; сбой снятия — в журнал |
| 8 | История ордеров недоступна при проверке позиции | своя непринятая позиция считалась ручной — вход второй позицией (5 %) | не проверено — новых входов нет, проверка повторяется |
| 9 | Сделка кита пришла в базу с опозданием | терялась (читалось только после последней) | каждый опрос — всё окно 2 часа, повторы отсекаются; в окне — по времени, опоздавшая старше окна сразу выходит |
| 10 | Нет базы бота | `SystemExit` мимо обработчика — служба падала | ошибка шага: журнал и пауза |
| 11 | Испорчен `state.json` (правка руками, обрыв) | падение на каждом шаге — торговля стоит | поля приводятся к типам; испорченная запись позиции забывается — своя находится по метке ордера |
| 12 | Испорчен `backtest_status.json`, мусор в cgroup | падение сравнения / запуска | числа — числа, иначе по умолчанию |
| 13 | Пересчёт не вышел по «Стоп» за 30 с | исключение из службы | `kill` |
| 14 | Очистка и бэктест бросили неожиданное исключение | служба падала, торговля стояла | сбой — в журнал, торговля идёт дальше |
| 15 | Истёкшие запреты бумаг не удалялись; мусор в `entered` | рост файла, падение очистки | очистка раз в 10 минут убирает их |

Сторона API (`Wallet-Tracker/wt_autotrade.py`): испорченный
`backtest_status.json` давал 500 («нет связи» во вкладке) — теперь числа
проверяются; позиция без объёма не показывается; бумага, исключённая больше
недели назад, — уже не «исключена».

## 11. OKX 50124 — запрет ключу, а не бумаге

Проверка на сервере 21.11.2026: ключ принят (eea.okx.com, права
`read_only,trade`), сигналов за сутки — по 79 бумагам, но все 7 попыток входа
(AAPL, BTC, MSFT, NVDA, HYPE, ETH, PUMP) OKX отклонил с `50124` («This API Key
does not have trading permission for the market»). Ручные позиции владельца
на тех же европейских бессрочных (H, RAVE) открыты — счёту рынок открыт,
закрыт **ключу**.

Ошибка бота: 50124 считался отказом по бумаге — каждая бумага исключалась на
неделю (BTC, ETH, NVDA… после исправления ключа пропускались бы ещё неделю).
Теперь:

- 50124 (`MARKET_CODES`) — пауза **рынка** (SWAP или FUTURES) на 30 минут:
  одна проверка ордером раз в полчаса, а не ордер на каждый сигнал; бумаги не
  исключаются. Ключ исправлен — следующий сигнал входит.
- Прежние недельные исключения за 50124 снимались при старте (переход с
  прежней версии; сделано — код убран в четвёртой ревизии).
- `key_problem` в состоянии — пока ордер на этом рынке не пройдёт; вкладка:
  «OKX не принимает ордера бота» с причиной.
- Отказы по самой бумаге (51001, 51155, 51156, 51010) — по-прежнему
  исключение бумаги на неделю.

Что сделать владельцу: в OKX → API открыть ключ и разрешить торговлю
фьючерсами; если такой настройки нет — создать новый ключ (права «Торговля»,
без вывода, IP сервера), вписать его `sudoedit /etc/whale-autotrade.env` и
`sudo systemctl restart whale-autotrade`.

Счётчик пропусков: каждая причина пропуска сигнала имеет код (`own_open`,
`market`, `no_inst`, `chase`…); служба считает их по часам за сутки (один
сигнал с одной причиной за час — один раз), вкладка показывает «Пропуски
сигналов за сутки» по-русски — причина «бот не входит» видна без сервера.

## 12. Выход вслед за китом в убытке (правило владельца, 21.11.2026)

Не пересиживаем: если **кто-то из китов сигнала** закрыл свою сделку по этой
бумаге **в убытке** (стоп, ликвидация или он увидел, что ситуация
изменилась), бот закрывает и свою позицию.

- Киты сигнала — кошельки от 1000 $ в окне 2 часа, сделавшие сигнал;
  запоминаются в записи позиции (`wallets`: кошелёк → его первая сделка в
  окне). Во вкладку кошельки не уходят.
- Закрытие кита — сделки `hl_fills` по той же бумаге и стороне: закрытие
  (3/4), разворот (5), ликвидация (6/7) — после его первой сделки в окне.
  Убыток — **сумма** `closed_pnl` этих закрытий меньше нуля: кит взял часть
  в плюс, потом закрыл остаток в минус, но в итоге в плюсе — сидим.
- Как закрываем: сверка счёта (раз в 15 с) спрашивает базу; убыток кита —
  снять свой тейк, затем рыночный ордер на свой объём (не больше: ручная
  докупка владельца остаётся), в режиме net — `reduceOnly`, в long/short —
  `posSide`. Сделка в журнале — «кит вышел в убыток».
- Не вышло (отказ, сбой связи) — запись «выходим» остаётся, тейк заново не
  ставится, повтор — раз в минуту; позиция исчезла — закрытие записывается по
  истории.
- Кит сигнала уже закрыл в убыток до нашего входа — не входим (пропуск
  «кит уже вышел в убыток»).
- Работает и при «Стоп»: «Стоп» — только без новых входов.
- Позиция, открытая прежней версией (без китов в записи), — киты
  восстанавливаются по базе: кто от 1000 $ открывал бумагу и сторону за 2 часа
  до сигнала (`wallets_at`); в журнале — «киты сигнала восстановлены по базе».
- После закрытия вход этой сделки помечен закрытым (`closed_ids`): позицию,
  докупленную владельцем руками на той же бумаге, бот своей не примет.

Бэктест это правило пока не моделирует (у него есть только `--whale-exit` —
выход на любом закрытии кита, не только в убытке): цифры бэктеста — для
стратегии «тейк или пересиживание».

## 13. Входим с крупными китами (правило владельца, 21.11.2026)

Случай: лонг BTC 21.11 21:43 UTC запустили мелкие киты (~42 тыс. $), а за те
же 2 часа против них 3 кошелька открыли шорты на 1,41 млн $ — в 33 раза
больше. Бот вошёл в лонг: встречных китов он не смотрел.

Теперь:

- Объём китов — сумма по кошелькам от 1000 $ в окне 2 часа (`whale_usd`).
- Решение — на момент входа (`balance`: окна за 2 часа до «сейчас»), а не по
  строке сигнала: за время опроса могли прийти киты в другую сторону.
- Против сигнала киты крупнее или поровну — в эту сторону не входим (пропуск
  «против — киты крупнее»).
- Крупных против от 2 — их сторона тоже кандидат в тот же момент
  (`_signal` для встречного окна): бот входит с крупными, если цена OKX
  проходит те же проверки (±2 %, не догоняем дальше 0,3 % от их средней).
- Один крупный против — сигнала в его сторону нет (нужно от 2 китов), но и в
  слабую сторону не входим.
- В записи позиции и во вкладке — объём китов за и против.

Почему бот написал «китов 3», а в окне было 4 лонга: в окно идут только
сделки открытия (`dir_code` 1/2). Если сделка кита записана как разворот
(«Short > Long», код 5) или по другой бумаге (например, `xyz:BTC`), она в
окно не попадает. Фильтра по прибыли за 30 дней у живого бота нет.

## 14. Вторая жёсткая ревизия (21.11.2026) — найдено и исправлено

Все проверки на эти ошибки падают на прежнем коде и проходят на новом.

| # | Ошибка | Чем грозила | Как теперь |
|---|---|---|---|
| 1 | Разворот кита (код 5) — одним кодом в обе стороны | кит развернулся **в нашу сторону** («Short > Long»: закрыл встречный шорт в минус и пошёл в лонг вместе с нами) — бот закрывал свой лонг по рынку | разворот считается выходом, только если он из нашей стороны (`dir`: «Long > Short» для лонга) |
| 2 | Сигнал «освежала» любая сделка по бумаге | киты вошли полтора часа назад, кто-то купил на 50 $ — бот видел свежий сигнал и входил | момент сигнала — сделка кита (кошелёк от 1000 $ в окне) |
| 3 | Китов проверяли на момент строки сигнала | от строки — 2 кита, а на момент входа (до 15 минут позже) старший уже старше 2 часов: вход с одним китом | на момент входа китов за 2 часа до «сейчас» — от 2, иначе пропуск «сигнал устарел» |
| 4 | Ответ на ордер выхода вслед за китом не дошёл / исполнение частичное | повтор через минуту закрывал ещё раз весь объём бота — при ручной докупке владельца на той же бумаге **закрывал ручную часть** | метка ордера выхода пишется в запись до отправки; повтор сначала находит прежние ордера по метке и закрывает только остаток своего объёма |

Частичный рыночный вход (исправлено 22.11.2026): ордер входа исполнился
частично (`partially_filled`), запись — `in_done: false`. Каждая сверка
счёта спрашивает ордер входа: доисполнился — объём, средняя цена и номинал
в записи — по всему исполненному (не больше заказанного), тейк ещё не тронут
— снимается и ставится заново на весь объём от новой средней цены; тейк уже
начал исполняться — не трогается, в журнал — предупреждение (остаток
закроет выход вслед за китом или вы). Ордер входа завершён (исполнен или
остаток отменён) — проверка прекращается.

## 15. Маржа всегда 5 % и разовое усреднение (правило владельца, 22.11.2026)

**Маржа входа — всегда 5 % капитала** × 10× (было 10 %, а при ручной сделке
владельца на счёте — 5 %). Ручная сделка входу не мешает и размер не меняет;
на её бумагу бот по-прежнему не входит.

**Разовое усреднение** (`average_down`, сверка раз в 15 с):

- условия — все сразу: позиция бота в минусе **больше 1 % движения цены**
  против нашей средней (`AVG_LOSS`; в приложении OKX это примерно −10 % PnL
  на маржу при 10×); кит сигнала **добрал** позицию по этой бумаге и стороне
  **после нашего входа** на сумму от 1000 $ (`whale_adds`); модуль включён
  (при «Стоп» не усредняемся); не идёт выход вслед за китом и вход не
  доисполняется;
- доливка — рыночным ордером 5 % капитала × 10× по текущей цене (объём —
  вниз по шагу; меньше минимума OKX — не делаем, в журнал);
- **один раз** на позицию: запись `avg` с меткой ордера `wtav…` пишется до
  отправки; сбой ответа или перезапуск — ордер находится по метке, второго
  нет; отказ биржи — не повторяем;
- после исполнения: объём, средняя цена (взвешенная), номинал — по всей
  позиции; тейк — **+1 % от новой средней на весь объём**, ставится сразу
  (тейк, который уже начал исполняться, не трогаем — предупреждение в
  журнал); выход вслед за китом закрывает весь усреднённый объём.
- Во вкладке у позиции — строка «Усреднено» с причиной.

## 16. Бэктест по актуальным правилам — `tools/autotrade_replay.py` (22.11.2026)

**Почему пересчёт «висел».** Служба запускала прежний бэктест-сетку
(`autotrade_backtest.py`): сотни наборов параметров и свечи Hyperliquid по
каждой бумаге из сигналов за весь период, с паузой 15 с между запросами (чтобы
не упереться в предел API). При сотнях бумаг это часы; вкладка всё это время
показывала только «считается», хода не было. И считал он старые правила
(10 %, пересиживание, без выхода за китом и усреднения).

**Теперь — повтор истории по правилам живого бота.** Сделки открытия китов

цены для тейка. Позиция ведётся по 5-минутным свечам OKX: тейк +1 % от
средней (лимит, комиссия мейкера), выход вслед за китом в убытке (через
15 с — сверка — по рынку), разовое усреднение (минус больше 1 % и добор кита
от 1000 $ после нашего входа — 5 % по цене порога, тейк от новой средней).

- Свечи — только под кандидатов и сделки, блоками по 100 (один запрос OKX),
  кеш на диске; пауза 0,15 с. 200 тысяч сделок китов — 4 секунды без сети.
- Ход — `run/progress.json`; служба переносит его в `backtest_status.json`,
  вкладка показывает «повтор: 40 % (… из … сделок китов), сделок 3, запросов
  к OKX 120».
- Капитал — как у счёта сейчас (из состояния торговли), период — 30 дней.
- Итог — `summary.json` того же вида (`kind: "replay"`): первые 3/4 и
  последняя 1/4 периода, все сделки, разбивки, пропуски по причинам, число
  усреднений, капитал на конец; `report.txt` — текстом.
- Проверки: `tests/autotrade_replay_test.py` (тейк, выход за китом, кит в
  плюс — сидим, усреднение и его условия, «входим с крупными», один крупный
  против, позиция одна, пауза 3 ч, нет на OKX, не догоняем, кит уже вышел,

Допущения повтора (честно): цена решения — открытие 5-минутной свечи;

## 24. Стоп за уровнем входа, усреднения нет (правило владельца, 24.11.2026)

  стопа (открылась за ним — по открытию), комиссия тейкера и проскальзывание;

  `average_down`, `_avg_fill`, `Signals.whale_adds`; в бэктесте — доливка.

Проверки: лонг и шорт (net и long/short) — не дошла на 10 $ — сидим, ровно до
стопа — выход; уровни после входа сдвинулись — стоп прежний; уровней нет —

## 27. Ревизия: тейк +1 %, стоп не дальше 1,5 %, сравнение вариантов (27.11.2026)

Владелец: «увеличь тейк, уменьши стоп, доведи до идеала». Что нашла ревизия
и что сделано.

**Стоп за уровнем был слишком далеко.** Диапазон 4 дней (24 свечи 4ч) у
крипты — 13–24 % (OKX, 27.11.2026: BTC 12,8 %, ETH 14,8 %, SOL 19,3 %, HYPE
24,3 %). Лонг разрешён ниже 40 % диапазона, значит стоп «0,5 % за
поддержкой» оказывался в 3–9 % от входа — против тейка +0,5 %. Для нуля
нужно было бы ~92 % сделок в плюс; лучший результат с китами — 73 %.
У приоритетного кита (уровни ему не помеха) стоп мог уйти на 20 %.
Теперь `core.entry_stop`: за уровнем, но **не дальше `STOP_MAX = 0.015`
(1,5 %) от цены входа** — ближний из двух; уровней нет — ровно 1,5 %
(раньше — без стопа). Стоп есть всегда, и у приоритетного кита тоже.

**Тейк +1 % (`TP = 0.01`, было +0,5 %).** Вход по рынку стоит 0,05 %
комиссии и ~0,05 % проскальзывания, тейк лимитом — 0,02 %: ~0,2 % на сделку,
при +0,5 % это 40 % тейка. На тейке +1 % был лучший результат с китами
(−0,92 $, 73 % в плюс). Соотношение 1 % к 1,5 % — для нуля нужно ~63 %
сделок в плюс.

Проверка на цене без китов (OKX, 12 монет × 60 дней, 5-минутные свечи,
вход каждые 15 минут, те же уровни и MA30, комиссии и проскальзывание):
любое сочетание тейка и стопа без китов — около −0,15…−0,25 % на сделку,
то есть ровно издержки: преимущество дают только киты. Стоп с пределом
1–1,5 % в среднем не хуже далёкого стопа за уровнем, но режет хвост. Период
был падением на 26–39 % (BTC −26 %, SOL −39 %), и фильтр уровней на нём
мешал (лонги у поддержки продавливало дальше) — вывод для этого периода,
не общий; поэтому — сравнение вариантов на китах (ниже).

**Сравнение вариантов в ночном бэктесте** (`--variants`, служба передаёт
его сама): после основного повтора — ещё 7 на тех же сделках китов, в
каждом одно изменение: тейк +0,5 % и +1,5 %; стоп не дальше 1 % и 2,5 %;
стоп только за уровнем (без предела); без уровней 4ч; без MA30. Свечи —
из того же кеша (новых запросов почти нет). Итог — `summary.json →
variants` (первый — текущие правила) и `report.txt`; во вкладке — раздел
«Бэктест: варианты правил» с разницей к текущим и лучшим вариантом.
Правила бота меняются только вручную — по этим данным.

**Найдено и исправлено:**
- свечи OKX не получены (отказ, обрыв сети) — раньше бот входил «как без
  уровней» и без стопа; теперь пропуск `candles`, а сигнал повторяется,
  пока свеж (15 минут: `Trader.retry`) — сигнал рождается только на сделке
  кита и сам бы не повторился; новый сигнал той же бумаги важнее
  повторяемого; у бумаги без истории (свечей нет) — как прежде, вход без
  фильтров со стопом 1,5 %;
- стоп по одной цене позиции (mark): испорченная цена в ответе OKX (фаззинг
  нашёл «1 $») закрыла бы позицию по рынку; теперь mark за стопом

## 28. До 3 позиций; варианты для скальпинга (правило владельца, 27.11.2026)

Владелец: «скальпинг со 100 % винрейтом, 24/7, сотни сделок в месяц»; «3
позиции максимум». 100 % сделок в плюс не даёт ни одна стратегия: так
выглядит только та, что не закрывает убытки (без стопа, до ликвидации); на
цене без китов тейк +0,5 % без стопа дал 84 % сделок в плюс — и минус по
итогу (раздел 27). Поэтому цель — итог и число сделок, а винрейт — следствие.

**Своих позиций — до `MAX_OPEN = 3`** (было — одна), на разных бумагах;
каждая — 5 % маржи × 10× (до 15 % капитала в марже, позиции 150 %
капитала), со своим тейком, стопом и выходом вслед за китом:
- состояние — `opens` (список); `open` — первая, для вкладки прежней версии;
  запись прежней версии (одна `open`) подхватывается; испорченная запись,
  повтор бумаги или больше трёх — отбрасываются (find_own узнает свою по
  метке ордера);
- вход: своих уже 3 — `own_open`; на бумаге уже своя — `own_same` (а не
  «ручная»); ручные владельца — по-прежнему не бота и мест не занимают;
- после входа бот разбирает и остальные сигналы того же опроса (раньше —
  стоп на первом входе), пока есть места;
- сверка: свои записанные не принимаются заново. Ревизия нашла здесь ошибку
  (mypy): имя `mine` (свои бумаги) перекрывалось списком ордеров из истории
  — со второй позиции на счёте бот принял бы свою записанную позицию
  заново и потерял бы её стоп и китов. Исправлено, проверка добавлена;
- закрытие одной (тейк, стоп, кит) — запись только её, место освобождается.

**Бэктест — те же 3 места.** Капитал (размер следующих входов) и рейтинг
китов — по сделкам, закрытым к моменту решения (`settle`, куча по времени
выхода): позиции закрываются не по порядку входа, и раньше итог сделки
попадал в капитал сразу на входе — взгляд в будущее при нескольких
позициях. В конце — закрытые к концу данных.

**Варианты (`--variants`) — для скальпинга**, к семи из раздела 27:
«тейк +0,3 %», «1 позиция», «пауза бумаги 30 мин», «вход лимитом» (лимит
по цене решения: исполнится, если за 5 минут после решения цена до него
дошла; мейкер 0,02 %, без проскальзывания; не дошла — `limit_miss`) и
«скальпинг: лимит, тейк +0,3 %, стоп до 1 %, пауза 30 мин». У каждого —
сделок в месяц (`per_month`); во вкладке — «N сделок (≈ M в месяц)».
Живые правила (тейк, пауза, вход рынком) не меняются, пока бэктест на
китах не покажет вариант с сотнями сделок и плюсом.

Вкладка: «Позиции бота: N из 3», у каждой — своя строка, тейк, стоп и
выход; ручные — отдельно. Причины пропуска: «у бота уже 3 позиции», «на

Найдено мутациями: фильтр «свои позиции — не ручные» ничего не менял (своя бумага

## 29. Вход — лимитом, не по рынку (правило владельца, 27.11.2026)

Владелец: «не маркетом». Вход по рынку стоил ~0,1 % (тейкер 0,05 % и
проскальзывание ~0,05 %), лимит «только мейкер» — 0,02 % без
проскальзывания: при тейке +1 % это ~0,08 % на каждой сделке.

**Как входит.** Ордер `post_only` (только мейкер: встал бы «в рынок» —
биржа его снимает) по лучшей цене своей стороны стакана: лонг — по лучшей
покупке (`bidPx`), шорт — по лучшей продаже (`askPx`); стакана нет — по цене
сделки; на шаге цены (лонг — вниз, шорт — вверх). Шаг тейка проверяется от
цены лимита. Запись «входим» (`entering`: цена лимита, до когда, объём,
киты, стоп) — до ордера, как раньше: служба упала — ордер найдётся по метке.

**Ждёт `LIMIT_WAIT_MS = 5 минут`**, не блокируя службу (раньше рыночный вход
ждал исполнения тут же): сверка раз в 15 с (`_resolve_limit`):
- исполнен — позиция по цене и объёму исполнения (не больше заказанного;
  цена дальше 5 % от лимита — порча: цена лимита), тейк — от неё;
- висит, время не вышло — ждём; вышло — снять остаток: исполненная часть —
  позиция и тейк на неё, ничего — входа нет;
- снят биржей без исполнения (post_only «в рынок») — входа нет, пропуск
  `limit_miss` (в том же шаге, если сразу);
- ордера нет (не дошёл до биржи, 51603) — 10 минут ждём, потом запись снята;
  отказ OKX при проверке — запись остаётся, повтор на сверке.
Пока лимит висит, других входов нет («лимит входа ещё ждёт исполнения» — по
одному), а сверка не «принимает» по метке позицию от его частичного
исполнения (это сделает `_resolve_limit` по истечении). Выходы — как были:
тейк — лимит, стоп и вслед за китом — по рынку (выход должен исполниться).

Убрано: доисполнение частичного рыночного входа (`_entry_fill`, `in_done`) —
лимит решается целиком одним разом.

**Бэктест** — вход лимитом по умолчанию (как у живого бота): по цене решения,
мейкер, без проскальзывания; исполнится, если за 5 минут после решения цена
(свечи после решения) до него дошла, иначе — `limit_miss`. Вариант «вход
рынком» — прежний вход для сравнения; «скальпинг» — тейк +0,3 %, стоп до
1 %, пауза 30 минут (вход — лимитом).

**Вкладка:** висящий лимит — своей строкой («SOL · лонг · лимит входа: ждёт
исполнения по … до …»; сервер отдаёт `pending`), в правилах — «вход —
лимитом «только мейкер» (не по рынку, ждёт 5 мин)».
Найдено мутациями: проверка «лимит висит — ждём» перед разбором ничего не меняла
(ниже висящий ордер ни подо что не подходит) — убрана; приём позиции по записи
прежней версии (с китами и стопом) — проверка добавлена. Проверки: торговля 135,
повтор 23, общее 5; мутации — 219 порч, 217 убиты, 2 эквивалентные.

## 31. Ревизия: почему бэктест всё ещё долгий; скорость и найденное (27.11.2026)

Владелец: «дальше считает долго — ревизия всего модуля каждой строки».

**Главная причина — служба ждала старый пересчёт.** При обновлении кода
служба перезапускалась только когда пересчёта нет: идущий пересчёт (до
6 часов) досчитывался старым кодом, и всё это время старым кодом шла и
торговля; правка одного бэктеста (`autotrade_replay.py`) службу не
перезапускала вовсе. Теперь обновление любого из трёх файлов (торговля,
общее, повтор) — перезапуск сразу; идущий пересчёт остановлен и заказан
заново (`Backtests.restart_for_update` → run.request): новая служба
начинает его новым кодом. Во вкладке — «код обновился — пересчёт начат
заново новой версией».

**Скорость повтора (процессор).** Профиль на 100 000 сделок китов (4
бумаги, цены гуляют — сделки открываются и закрываются): без вариантов —
26 → 11 с, с 12 вариантами — 97 → 36 с; база 300 000 — 5,2 → 3,8 с и 8,8
→ 7,2 с. Что съедало: каждый вариант заново считал на том же сигнале
объёмы за и против, уровни 4ч, MA30 (теперь `Replay.cached` — один расчёт
на сигнал и момент на все варианты); объём китов окна суммировался заново
на каждой сделке (теперь `Window.whale_n` — по ходу, целыми, тем же
правилом, что `count`); на каждый запрос о выходе китов открывалась база
(теперь `Signals(keep=True)` — одно соединение на проход); свеча
искалась перебором блока (теперь словарь); кеш свечей переписывался на
диск каждые 2 с (теперь раз в минуту и в конце).

**Скорость (сеть).** С тремя позициями почти каждый сигнал доходит до
свечей — первый прогон качает 5-минутные свечи почти всех бумаг с китами
за 30 дней (~90 запросов на бумагу), дальше — из кеша. Раньше запросы шли
по одному: пауза 0,15 с плюс ожидание ответа. Теперь — до 4 сразу
(`ThreadPoolExecutor`), общая частота — `Limiter` (не чаще раза в 0,11 с
на все потоки: у OKX 20 запросов за 2 с), соседние блоки (предыдущий — для
MA30 и уровней, два следующих) — заранее; сбой — до 3 попыток (раньше
сбой молча давал «нет цены» и искажал повтор). Замер (40 бумаг, ответ
0,2 с): ~1180 → 553 с при паузе 0,15 (упор — в частоту); итог тот же.
В ходе пересчёта во вкладке — «осталось ≈ N мин».

**Найдено в торговле:**
- кит сигнала закрылся в убытке, пока лимит входа висел, — бот всё равно
  входил и на следующей сверке выходил по рынку в минус; теперь лимит
  снимается (бэктест — так же: выход кита до исполнения лимита — входа нет);
- стакан не получен (отказ OKX) — падал весь шаг; теперь лимит по цене
  сделки.
Проверки: торговля 140, повтор 27, общее 5; мутации всего изменённого (бэктест,
лимит, обновление кода, ход пересчёта, окна китов) — 89 из 89.

## 34. Вход по рынку, но не дальше 0,3 % от китов (правило владельца, 27.11.2026)

Владелец: «вход маркет ордером, но соблюдаем 0,3 % и не гонимся за ценой».
Лимит «только мейкер» (раздел 29) часто не исполнялся: цена уходила, а вход
пропадал. Теперь — ордер `ioc` (исполнить сразу, остаток снять) с ценой-
границей: средняя китов × (1 ± `CHASE` = 0,3 %), на шаге цены внутрь (лонг —
вниз, шорт — вверх). Биржа исполняет по рынку всё, что есть не хуже границы;
дальше границы — не исполняет: за ценой не гонимся, проскальзывание за 0,3 %
невозможно. Шаг тейка проверяется от текущей цены, тейк ставится от цены
исполнения.

**Проверка исполнения** (`_resolve_entry`, `ENTRY_WAIT_MS = 1 минута`, обычно
ответ сразу в том же шаге): исполнен целиком или частично — позиция по
исполненному (не больше заказанного), тейк — от цены исполнения (цена
дальше 5 % от рынка — порча: берётся цена рынка на момент ордера); ничего
не исполнено (цена ушла за 0,3 %) — входа нет, пропуск `limit_miss` в том же
шаге; ордер почему-то висит дольше минуты или кит сигнала закрылся в
убытке — снять, исполненная часть — позиция. Ордер не найден (51603) — 10
минут ждём, потом запись снята; отказ OKX при проверке — повтор на сверке.
Стакан (`Okx.best`) больше не нужен — убран.

0,05 %), но цена входа не хуже границы 0,3 %; вариант «вход лимитом
(мейкер, 5 мин)» — прежний вход для сравнения. «Против китов» — один
вариант (по рынку).

**Вкладка:** «вход — по рынку, но не хуже средней китов ±0,3 % (дальше — не
входим, за ценой не гонимся)»; непроверенный ордер — строкой «SOL · лонг ·
вход»; пропуски — «цена ушла за 0,3 % от китов — вход не исполнился».

Проверки: торговля 140, повтор 31 (граница входа: цена 100 290 при китах по

- `TP = 0.015` — тейк +1,5 % (было +0,8 %). В прошлом бэктесте вариант
  «тейк +1,5 %» был на 18 $ лучше текущего; стоп остаётся 1,5 % — тейк и
  стоп поровну: для нуля нужно чуть больше половины сделок в плюс (с

- Уровни графика 4ч убраны полностью: `core.level_ok`, `level_stop`,
  `entry_stop`, `LEVEL_*`, `Okx.range_levels`, `Trader.level_check` — их нет.
  Свечи 4ч не запрашиваются. Стоп — `core.fixed_stop` прямо в `try_enter`.
  Пропуск «candles» теперь — только сбой свечей 15м для MA30 (сигнал свеж 15
  минут — следующий опрос повторит).
- Приоритетный кит — без «против крупнее» и MA30 (уровней больше нет).

**Бэктест — один расчёт.** Убраны: варианты (`Rules`, `VARIANTS`,
`--variants`, `replay_all`, общие расчёты `memo`/`rows_cache`), разбор
сигналов (`Study`, `edge`), свечи 4ч (`hours`). `Replay.run` — один проход
по сделкам китов с правилами живого бота (константы `lv` и `core`
напрямую — расхождения быть не может). Одиночный сигнал — только
приоритетного кита по рейтингу повтора (`sig.priority` обновляется на

(итог первой и второй половины периода); во вкладке — «До комиссий» и
«Половины периода» («плюс в обеих — похоже, не случайность»).

Служба запускает бэктест без `--variants`; вкладка больше не рисует
варианты и разбор (старые поля в прежнем итоге не мешают).

## 38. Против китов, кит — снова от 1000 $ (правило владельца, 28.11.2026)

Бэктест раздела 37 (кит от 10 000 $): 447 сделок, 46,5 % в плюс, PF 0,92,
итог −17,77 $; до комиссий +12,27 $, комиссии 30,04 $; половины −33,44 /
+15,66 $. Владелец: «а давай против китов и с 1000 долларов».

- `MIN_WHALE_USD = 1000` — как до раздела 37.
- `AGAINST = True` — сигнал находится как прежде (киты, «против — не
  крупнее», «кит уже вышел в убыток», приоритетный кит — по стороне китов), а
  сделка — в обратную сторону: в `try_enter` после проверок китов
  `s["side"]` меняется на обратную, и дальше всё — по стороне сделки: «не
  хуже цены китов» (шорт против их лонгов — не дешевле их средней), MA30
  (шорт — цена ниже MA30), стоп 1,5 %, тейк +1,5 %, граница IOC.
- Выхода вслед за китом в убытке нет (его убыток — наш плюс): позиция и
  запись «входим» помечены `fade`; `_follow_one` не смотрит на китов у
  таких позиций; ордер входа не снимается из-за убытка кита; подхват после
  падения службы сохраняет `fade` из записи «входим». Позиции прежних версий
  (без `fade`) — как были, с выходом вслед за китом.
- Рейтинг китов — как прежде: сделка засчитывается китам сигнала; высокий
  наш винрейт с китом — значит, против него выгодно.
- Бэктест — тот же код (`lv.AGAINST`): сторона сделки обратная, выхода вслед
  за китом нет.
- Вкладка: у позиции — «· против китов», выход — «тейк или стоп (против
  китов — выхода вслед за китом нет)»; сервер отдаёт `fade`.

Тесты по направлению китов включают `AGAINST = False` сами (Base,
ReplayTest); против китов — `AgainstTest` (сторона, догон и MA30 по стороне
сделки, без выхода за китом, стоп работает, ордер не снимается, подхват
помнит `fade`, по умолчанию в коде — True) и бэктест `test_against_whales`.

Ожидание по данным: до комиссий у сигналов «за китами» был небольшой плюс
(+5 и +12 $ за 30 дней) — против китов он, скорее всего, станет минусом;
решит бэктест.

Уточнения владельца (28.11.2026): цена входа против китов — шорт только от
+1 % выше средней цены китов, лонг — от 1 % ниже (`CHASE = −0.01`: проверка
и граница IOC по стороне сделки; цена ещё не там — пропуск «chase»). MA30
15м — по стороне сделки: в шорт не входим, когда цена выше MA30, в лонг —
когда ниже. Мутационную проверку на время настройки бота владелец просил не
запускать.
