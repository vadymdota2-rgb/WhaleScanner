# Оплата Премиума — спецификация модуля

Модуль выдаёт Премиум после оплаты и снимает его, когда срок кончился.
Деньги проходят через него в двух видах: звёзды Telegram (XTR) и USD₮ в
сети TON. Всё, что решает «выдать или нет», — чистые функции; всё, что
пишет в базу, — транзакции; всё, что пришло извне, — проверяется до
использования и чистится до журнала.

| Часть | Файл |
|---|---|
| Договор с ботом (что можно звать и откуда) | `premium.h` |
| Правила: тарифы, вводная цена, срок, адреса TON, приём перевода, разбор команды, чистка журнала | `premium_logic.h` (без базы, сети, часов и состояния) |
| База, сеть, сообщения | `premium.cpp` |
| Запрос к чужому серверу с пределами | `safe_http.h`, `safe_http.cpp` |
| Ожидание занятой базы (`busy_timeout`) и вызовы модуля | `main.cpp` (`initDB`, главный цикл, `/grant`, `/autorenew`) |
| Счета и цены в звёздах и USD₮ | API: `whale_api.py` (`STAR_PLANS`, `USDT_PLANS`, `pay_usdt`) в репозитории Wallet-Tracker |
| Проверки | `tests/premium_test.cpp`, `tests/premium_policy.py`, `tests/safe_http_test.py`, `tests/fuzz/premium_fuzz.cpp`, `tools/coverage.sh`, `tools/mutate.py` |
| Образцы ответов — договор с toncenter и Telegram | `tests/fixtures/toncenter_jetton_transfers.json`, `telegram_*.json` |
| Договор с API: тарифы, вводная цена, памятка, кошелёк, столбцы счёта | `tests/fixtures/premium_contract.json` — тот же файл в Wallet-Tracker; сверяют `tests/premium_test.cpp` (contract), `tests/premium_policy.py` и `tests/test_premium_contract.py` у API |

## Как течёт оплата

**Звёзды.** Счёт создаёт API (`createInvoiceLink`) с полезной нагрузкой
тарифа. Telegram спрашивает бота «можно ли платить» (`pre_checkout_query`)
— бот отвечает за 8 секунд (у Telegram — 10): тариф известен, валюта XTR,
сумма — ровно цена тарифа, вводная цена — только своему покупателю и в
её окно. После списания приходит `successful_payment`: бот ещё раз сверяет
тариф, сумму и валюту, записывает платёж в `premium_payments` и продлевает
срок — одной транзакцией. Повтор того же платежа узнаётся по
`telegram_payment_charge_id` (уникальный) и ничего не продлевает.

**USD₮.** API кладёт счёт в `ton_invoices` (`kind='usdt'`, памятка
`WT-XXXXX`, сумма в миллионных долях, срок 30 или 365 дней) и показывает
человеку кошелёк приёма и памятку; приложение отправляет перевод жетона с
памяткой-комментарием. Пока есть счёт моложе часа (столько API показывает
его человеку), бот раз в 20 секунд спрашивает toncenter (только переводы
USD₮ на свой кошелёк, 50 последних); живые счета все старше — раз в 2
минуты (`premium::pollDue`: запросов по такому счёту в 6 раз меньше,
опоздавшая оплата находится не позже чем через 2 минуты). Затем бот
для каждого годного перевода находит живой счёт с той же памяткой и одной
транзакцией занимает счёт (`active → paid`, хеш перевода) и продлевает срок.

### Состояния счёта USD₮

```
           API: pay_usdt
                │
                ▼
            ┌────────┐  перевод с памяткой, сумма ≥ 98 %,   ┌──────┐
            │ active │ ─────── одной транзакцией ─────────▶ │ paid │
            └────────┘       с продлением срока             └──────┘
                │
                │  старше суток (created_at ≤ сейчас − 86 400)
                ▼
            ┌─────────┐
            │ expired │
            └─────────┘
```

Других переходов нет. `paid` и `expired` — конечные. Недоплата, перевод
на чужой кошелёк, чужой жетон, сорванная транзакция — счёт остаётся
`active` (недоплата — одна строка в журнал на перевод).

## Инварианты

Правила, которые обязаны выполняться при любом входе. Их проверяют
примеры, свойства на случайных входах (фиксированное зерно — нарушение
воспроизводится), фаззинг libFuzzer и мутационная проверка.

1. **Премиум выдаётся только за свою цену.** Звёзды — тариф известен,
   валюта `XTR`, сумма — целое, равное цене тарифа (не дробь, не строка,
   не число больше `LLONG_MAX`: `4294967546` не превращается в `250`).
2. **Вводная цена — только своему и вовремя.** Нагрузка
   `premium_30_intro:<chat>:<до>` из цифр без хвостов; покупатель — тот же
   чат; сейчас ≤ `до` + 900 секунд.
3. **USD₮ засчитывается только настоящий, только наш и только один раз.** Перевод не
   сорвался (`transaction_aborted` — логическое `false`); мастер-контракт —
   USD₮ (`0:B113…1DFE`); получатель — наш кошелёк (сырой адрес, сверенный
   по контрольной сумме CRC-16 из человеческого вида — фильтру обозревателя
   на слово не верим); сумма — целое из цифр ≥ 1 USD₮ и ≥ 98 % счёта
   (без переполнения); памятка — живого счёта; сделан не раньше счёта
   (запас 10 минут); его хеш ещё не оплатил другой счёт.
4. **Одна оплата — один срок.** Повтор платежа звёздами не продлевает;
   оплаченный счёт USD₮ не занимается второй раз.
5. **Оплачен — значит выдан.** Запись оплаты (платёж или `paid` у счёта) и
   новый срок — одна транзакция `BEGIN IMMEDIATE … COMMIT`: либо оба, либо
   ни одного. Сбой — откат, счёт USD₮ остаётся `active` и пробуется снова.
6. **Срок только растёт и только в разумных пределах.** Действующий
   продлевается с конца, кончившийся — с текущей секунды; начало
   действующего не сдвигается; дни 1…3650; срок, не помещающийся в
   `long long`, — отказ.
7. **Граница срока — строгая.** Премиум действует, пока `expire > сейчас`;
   при `expire == сейчас` уже кончился. Счёт USD₮ живёт ровно сутки.
8. **Сервисный аккаунт — никогда не подписчик**: ни выдачи, ни отметки
   (снимается при запуске), ни в выборке подписчиков, ни письма об окончании.
9. **Истёкшие снимаются согласованно.** Список истёкших и снятие отметки —
   одна транзакция: продление от API в ту же секунду не даёт письма
   «Премиум закончился» тому, у кого он есть.
10. **Журнал не подделать.** Любая строка извне (нагрузка, валюта, ответ
    Telegram, ошибка SQLite, памятка, номер чата) — в журнал через
    `logSafe`: управляющие знаки — пробелом, не длиннее 300 байт, обрезка по
    границе знака UTF-8.
11. **Память не растёт.** «Сказано один раз» (`premium::Once`) — не больше
    1000 ключей; выборка подписчиков — кусками по 500 параметров.
12. **Сбой схемы выключает оплату целиком.** Нет таблицы людей, не
    добавился столбец, не встал индекс — `initPremium` возвращает false, и
    до исправления: на счёт — «оплата временно недоступна», опроса нет,
    выдачи нет.

## Модель угроз

От чего модуль защищён и как:

| Угроза | Что делает модуль |
|---|---|
| Перевод чужого жетона «USD₮» (подделка мастер-контракта) | мастер сверяется с адресом настоящего USD₮ в сыром виде |
| Обозреватель не применил фильтр и отдал переводы на чужие кошельки | получатель сверяется с нашим кошельком у нас |
| Человек платит себе с памяткой нашего счёта | то же: получатель — только наш кошелёк |
| Повтор одного платежа звёздами (Telegram прислал дважды) | уникальный `telegram_payment_charge_id`; повтор ничего не продлевает |
| Переслать ссылку на счёт со скидкой другому или оплатить позже | вводная цена привязана к чату и окну (+15 минут) |
| `250.9`, `"250"`, `4294967546`, `1e400` в сумме | только целое поле; сужения до `int` нет |
| `"123abc"`, `" 123"`, `"+5"` в сроке, номере, сумме | только цифры, до 18 знаков (`strictInt`; `stoll` в модуле запрещён) |
| Испорченный, усечённый, гигантски вложенный JSON от обозревателя или Telegram | разбор без исключений (`parse(…, false)`), поля — только нужного типа; фаззинг libFuzzer |
| Спам чужими жетонами вытесняет оплату из 50 последних переводов | запрос только по мастеру USD₮ |
| Перевод строки, ESC-коды, мегабайт текста в ответе — подделка журнала | `logSafe` |
| SQL-инъекция через памятку, нагрузку, номер чата | SQL — только литералы, данные — через `bind` (проверяется `tests/premium_policy.py`) |
| API пишет в базу в ту же секунду — «database is locked», звёзды списаны, Премиума нет | `busy_timeout` 5 с у соединения бота; транзакции `BEGIN IMMEDIATE` |
| Гонка продлений бота и API | чтение срока и запись — внутри одной транзакции записи |
| Подменённый или взломанный toncenter / Bot API шлёт гигабайтный ответ, держит ответ «по байту» часами, перенаправляет на внутренний адрес, отвечает по http | `safe_http` (`httpsCapped`): только https с проверкой сертификата и имени; перенаправления не выполняются; ответ больше предела (toncenter — 1 МБ, Bot API — 64 КБ) — отказ, а не обрезка; срок — на весь ответ; сжатие не просим и не распаковываем. Проверено на настоящих локальных серверах (`tests/safe_http_test.py`) |
| JSON с вложенностью в сотни тысяч уровней — переполнение стека | разборщик и удаление без рекурсии; проверено под ASan на 500 000 уровней |
| Старый перевод с совпавшей памяткой оплачивает новый счёт | перевод засчитывается, только если сделан не раньше счёта (запас 10 минут на расхождение часов) |
| Один перевод (хеш) — на два счёта (подделанный ответ с тем же хешем и другой памяткой) | хеш, уже оплативший счёт, второй раз не засчитывается; перевод без хеша или времени не принимается |
| HTML (`<b>`, `&`) в ответе Telegram ломает сообщение владельцу — и он не узнаёт о сбое | строки извне в сообщениях владельцу — `logSafe` и `escapeHtml` |
| Подмена вшитого разборщика JSON (`json.hpp`) в репозитории | SHA-256 закреплён в `tests/premium_policy.py` — релиз nlohmann/json 3.11.3, сверен побайтно |
| Подложенный опасный код (человек или ИИ-агент) | правила кода: разрешённые `#include`, запрещённые вызовы (процессы, файлы, `stoll`, `new`, `try`), сеть — только toncenter и Bot API, запись — только в `Tx`; правила сами проверены подлогами |

Bot API у бота — только по https (`WHALE_TG_API` по умолчанию —
`https://api.telegram.org`): подставной сервер по http оплату не получит.

Чего модуль не обещает: защиты от toncenter, который врёт правдоподобно и
согласованно (сверка с вторым независимым обозревателем — возможное
развитие); защиты сервера, на котором кто-то правит базу руками.

## Конкурентность

- База — одно соединение бота под `dbMutex` (все функции модуля берут его
  сами; функции с суффиксом `Locked` зовутся уже под ним). API — отдельный
  процесс со своим соединением к той же базе (WAL).
- Запись денег и сроков — только внутри `Tx` (RAII): `BEGIN IMMEDIATE`,
  `commit()` или откат в деструкторе. Запросы — `Stmt` (RAII): `finalize`
  в деструкторе.
- `initPremium` — один раз при запуске, до потоков. `pollUsdtPayments` — из
  одного потока (главный цикл). Остальное — из любого потока.
- Ожидание чужой записи — до 5 секунд (`busy_timeout`, `initDB`); не
  дождались — транзакция не начинается, ничего не записано.

## Отказы и что делать владельцу

Бот сам пишет владельцу в личный чат с ботом (`OWNER_CHAT_ID`), когда деньги
пришли, а Премиум выдать не вышло:

- **«⚠️ Оплата: звёзды списаны (…, chat N, charge C), а Премиум на D дн.
  выдать не вышло — выдать вручную.»** — выдать командой
  `/grant N D` в том же чате. Платёж в историю не записан (откат), повтор
  от Telegram пройдёт сам.
- **«⚠️ Оплата: пришло X USD₮ по счёту WT-…, а Премиум выдать не вышло.
  Бот повторяет каждые 20 с»** — счёт остался `active`, бот пробует сам,
  пока счёт жив (сутки). Не прошло — `/grant N 30` (или 365 для годового).
- **`[PREMIUM][FATAL] Module init failed`** в журнале при запуске — оплата
  выключена; причина — строкой выше (`migration failed` / `payment tables
  failed`). Люди видят «оплата временно недоступна» и деньги не теряют.
- **`[USDT] адрес кошелька приёма не разобран`** — `TON_WALLET_ADDRESS` в
  окружении бота испорчен; оплата USD₮ не проверяется, пока не исправить.
  Кошелёк у бота и у API должен быть один.

Команды владельца: `/grant <chat_id> <дней 1–3650>` — выдать вручную;
`/autorenew` — отменить оставшиеся автопродления звёздами.

## Скорость

Замер на 20 000 людей (из них 2 000 подписчиков, `-O2`): выборка
подписчиков для рассылки — 17 мс на всех, 42 мкс на 50 человек; проверка
одного человека — 4 мкс; проход опроса USD₮ с 50 переводами — 0,55 мс;
снятие истёкших — 0,6 мс. Узкое место — сеть, а не процессор, поэтому
сокращены запросы к toncenter (см. выше), а не вычисления.

## Качество

Проверяется на каждом push (`.github/workflows/tests.yml`):

- **Тесты** (`tests/premium_test.cpp`): примеры на каждое правило; свойства
  на 100 000 случайных сумм и 20 000 адресов туда-обратно; 50 000 случайных
  ответов обозревателя; SQLite в памяти — звёзды, USD₮, повторы, отказы,
  сбои COMMIT и вставки, занятая база, отмена автопродлений, ручная выдача,
  границы сроков до секунды на подменённых часах, образцы ответов; тексты
  на 16 языках. Под ASan и UBSan.
- **Покрытие** (`tools/coverage.sh`, clang + llvm-cov): 100 % строк,
  ветвлений, функций и областей у `premium.cpp` и `premium_logic.h`; ниже по
  любой мере — провал. Пути сбоев покрыты настоящими средствами SQLite:
  триггер с RAISE, отложенный внешний ключ на COMMIT, удалённая таблица,
  база только на чтение, чужая транзакция.
- **Два компилятора**: g++ и clang, оба под ASan и UBSan; весь бот
  собирается обоими с `-Werror`. Модуль — ещё и clang `-Weverything`.
- **Нагрузка и память**: 20 000 человек — выборка подписчиков < 2 с,
  проверка всех по одному < 4 с; 2 000 проходов опроса со 100 000 новых
  переводов — проход < 50 мс, память растёт меньше чем на 512 КБ (без
  предела у «сказано один раз» — на 1,4 МБ), незакрытых запросов нет.
- **Тексты**: 9 сообщений оплаты на 16 языках — перевод, а не английский;
  между числом и словом — неразрывный пробел; в китайском и японском — без
  пробелов вокруг числа; во французском — неразрывный пробел перед «: ; ! ?».
- **Мутации** (`tools/mutate.py`): каждая порча кода (сравнения, логика,
  константы, возвраты) убивается тестами; равносильные перечислены с
  причиной, устаревшая запись — провал.
- **Фаззинг** (`tests/fuzz/premium_fuzz.cpp`, libFuzzer + ASan + UBSan):
  инварианты правил на любых байтах; затравка — образцы ответов.
- **Статический анализ**: GCC с `-Wconversion -Wsign-conversion -Wshadow
  -Wold-style-cast …` как ошибками; clang-tidy (`bugprone`, `cert`,
  `cppcoreguidelines`, `concurrency`, `performance`, `readability` и др.,
  `.clang-tidy`) без замечаний.
- **Правила кода** (`tests/premium_policy.py`) — и проверка, что каждое
  правило ловит подложенное нарушение; хеш `json.hpp`; защиты `safe_http`
  не убираются молча.
- **Атаки на сеть** (`tests/safe_http_test.py`): свой удостоверяющий центр
  и настоящие https/http-серверы — http, чужой сертификат, чужое имя,
  перенаправление, огромный ответ с длиной и без, ответ «по байту», сжатие.

Запустить локально: `FULL=1 SANITIZE=1 bash tests/run.sh` (нужны g++,
clang с libclang-rt, clang-tidy, libsqlite3-dev, libcurl, Boost);
мутации — `python3 tools/mutate.py` (~20 минут на 4 ядрах).
